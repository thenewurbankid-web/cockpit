Tools API

Project-board sync and the GitHub comment bridge.

9 modules, 30 documented exports. Version next. All packages.

tools/api-coverage

  • checkJSDoc coverage ratchet (epic #463, slice 2). Exports: ROOTS, compare, gapsOf, listFiles, measure, parseJsDoc

tools/github-comment-bridge/src

  • claudeRunnerExports: buildPrompt, runClaude
  • configConfiguration is read entirely from environment variables. Exports: loadConfig
  • githubGitHub REST client — a thin wrapper over @octokit/rest (the official GitHub SDK, #94): Octokit owns the HTTP/auth/pagination/rate-limit/retry mechanics, this module only decides *what* to call and returns plain data (... Exports: createGitHubClient
  • jsonStoreExports: createJsonStore
  • pollerExports: establishBaseline, excerpt, extractIssueNumber, pollOnce, resolveBotLogin, summarizeRun
  • triggerThe one supported trigger convention (see README): a comment whose FIRST LINE is exactly "/claude <instruction text>" (case-sensitive, must start the comment). Exports: parseTrigger

tools/project-board

  • planPure planning logic for the project-board hygiene sync. Exports: DEFAULT_ARCHIVE_DAYS, STATUS, isOlderThan, planActions, statusForState
  • taxonomyBoard taxonomy: Module -> Sub-module. Exports: AREAS, MODULES, OTHER, SUB_MODULES, TAXONOMY, areaOf, checkArea
