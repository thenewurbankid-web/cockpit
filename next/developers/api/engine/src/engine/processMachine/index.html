PROCESS_MACHINE#

const PROCESS_MACHINE: Readonly<{ context: { completedSteps: number; currentStepId: any; pendingControl: any; processId: any; totalSteps: number; }; id: "process"; initial: "queued"; states: { cancelled: { type: string; }; done: { type: string; }; failed: { on: { CANCEL: { actions: string[]; target: string; }; RETRY: { actions: string[]; target: string; }; }; }; paused: { on: { CANCEL: { actions: string[]; target: string; }; RESUME: { actions: string[]; target: string; }; }; }; queued: { on: { CANCEL: { actions: string[]; target: string; }; START: { actions: string[]; target: string; }; }; }; running: { initial: string; on: { FINISHED: { actions: string[]; target: string; }; STEP_FAILED: { actions: string[]; target: string; }; }; states: { active: { on: { CANCEL: { actions: string[]; target: string; }; PAUSE: { actions: string[]; target: string; }; STEP_COMPLETED: { actions: string[]; }; }; }; stopping: { on: { YIELDED: ({ actions: ...[]; guard: string; target: string; } | { actions: ...[]; guard?: undefined; target: string; })[]; }; }; }; }; }; }>

Defined in: src/engine/processMachine.mjs:58

The machine. Valid XState v5 config; see the header for why it is not fed to createMachine() here.

Shape of the lifecycle in one breath: a process is queued until something starts it; while running it either works (active) or is winding down because someone asked it to (stopping); a step failing fails the whole process (recoverable with RETRY); running out of steps finishes it.

RUNNING_SUBSTATES#

const RUNNING_SUBSTATES: readonly string[]

Defined in: src/engine/processMachine.mjs:38

Inside running: active is executing steps; stopping means a pause or cancel has been asked for and the machine is waiting for the step in flight to reach a yield point. Control is cooperative — a step cannot be torn down mid-syscall — and this is how that truth is modelled without inventing a seventh top-level state that #292's pill and list would have to learn.

transition()#

transition(statePath, eventType, context?): object

Defined in: src/engine/processMachine.mjs:204

Take one event. Returns { value, actions, changed } — the next fully resolved state path, the action names the transition declared (the caller performs them; this module never has side effects), and whether the state path moved — or null when the event is not accepted in this state, so a caller can reject "resume a process that is not paused" by name rather than by silently doing nothing.

Handlers are looked up on the state itself, then on each ancestor, which is how XState's event bubbling works and is why STEP_FAILED declared on running fires while the machine sits in running.active.
